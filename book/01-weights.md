# 第 1 章 读取权重文件

> 状态：初稿。本章的代码已通过自造测试文件上的对拍，还没有在真实的模型权重上跑过。

## 要解决的问题

一个大模型发布出来，主体就是一组权重：几百到几千个多维数组，每个有名字、元素类型和形状。推理引擎要做的第一件事，是把它们从磁盘上原样读出来。

“原样”两个字是这一章的全部重点。如果某个张量读错了一个字节，或者两个张量的名字对调了，后面的程序不会崩溃，只会算出一个略有不同的结果。所以这一章的验收标准定得很死：

**对文件里的每一个张量，我们读到的名字、类型、形状和全部字节的校验和，必须与一份独立的参考实现完全一致。**

## safetensors 格式

现在的开源模型大多用 safetensors 格式发布权重。它的布局只有三段：

```
偏移 0        8                8+N                    文件末尾
     ┌────────┬────────────────┬──────────────────────┐
     │ N      │ JSON 头        │ 数据区               │
     │ 8 字节 │ N 字节         │ 所有张量的原始字节   │
     └────────┴────────────────┴──────────────────────┘
```

- 开头 8 个字节是一个小端序的 64 位无符号整数 N，表示 JSON 头的长度。
- 接下来 N 个字节是一段 UTF-8 编码的 JSON。
- 剩下的全部是数据区。

JSON 头是一个对象，键是张量的名字，值描述这个张量：

```json
{
  "model.embed.weight": {"dtype": "BF16", "shape": [50, 16], "data_offsets": [0, 1600]},
  "__metadata__": {"format": "pt"}
}
```

`data_offsets` 是 `[起点, 终点)`，相对于数据区的起点而不是文件的起点。`__metadata__` 是一个特殊的键，存放任意的字符串键值对，不是张量。

这个格式没有压缩，数据就是数组在内存里的样子。这意味着我们可以直接把文件映射进内存，让每个张量的指针指向映射区域的内部，一个字节都不用拷贝。

## 实现

代码在 [`src/st.h`](../src/st.h) 和 [`src/st.c`](../src/st.c)。对外只有四个函数：

```c
int  st_open(st_file *f, const char *path, char *err, size_t errcap);
void st_close(st_file *f);
const st_tensor *st_find(const st_file *f, const char *name);
```

`st_open` 做三件事。

**第一，映射文件。** 用 `mmap` 把整个文件只读地映射进地址空间。几十 GB 的文件也是瞬间完成，因为操作系统只在我们真正访问某一页时才去读磁盘。

**第二，读头长度。** 这 8 个字节我们逐字节拼起来，而不是把指针强转成 `uint64_t *` 去读：

```c
for (int i = 7; i >= 0; i--) hlen = hlen << 8 | base[i];
```

这样写不依赖运行机器的字节序，也不会有未对齐访问的问题。

**第三，解析 JSON 头。** 这是代码量最大的部分。我们没有引入 JSON 库，而是写了一个只够用的解析器，大约两百行。它只认识这个格式里会出现的东西：字符串、非负整数、数组和对象；遇到 `__metadata__` 或不认识的字段就整体跳过。

字符串解析是其中唯一有点麻烦的地方。张量的名字是任意的 Unicode 字符串，JSON 允许把字符写成 `\uXXXX` 的转义形式，超出基本平面的字符还会写成两个转义组成的代理对。我们把它们全部解码成 UTF-8，这样同一个名字不管在文件里怎么转义，读出来都是同一串字节。

## 不信任输入

权重文件是从网上下载的。一个推理引擎如果因为文件里的一个数字写错了就越界读内存，那它离商用还很远。所以读取器对每一个张量都做这些检查，任何一项不满足就报错退出：

| 检查 | 防的是什么 |
| --- | --- |
| 头长度不超过文件大小 | 一上来就越界 |
| `data_offsets` 的起点不大于终点，终点不超过数据区大小 | 张量指针指到映射区域之外 |
| 字节数恰好等于各维度之积乘以元素大小 | 形状和数据对不上 |
| 计算各维度之积时检查乘法溢出 | 用一个巨大的形状让乘积回绕成小数字，骗过上一条检查 |
| `dtype` 必须是已知类型 | 默默把未知类型当成别的类型 |
| 张量名不能重复 | 后一个悄悄覆盖前一个 |
| JSON 头结束后不能有多余内容 | 格式不合规的文件 |

溢出检查那一条值得多说一句。形状 `[2^62, 4]` 的 32 位浮点张量，字节数是 2^62 × 4 × 4 = 2^66，在 64 位整数里回绕后恰好是 0。如果不检查溢出，一个声称自己有 2^64 个元素、实际数据为空的张量就能通过校验。测试里的 `bad_overflow` 就是这个例子。

还有一项检查目前没有做：两个张量的数据区间不应重叠。重叠不会导致越界，所以先不处理，记在这里。

## 如何验证正确

验证靠两份独立的实现互相比对。

- [`tools/st_dump.c`](../tools/st_dump.c) 用我们的读取器打开文件，对每个张量输出一行：校验和、类型、形状、名字。
- [`tests/ref_dump.py`](../tests/ref_dump.py) 用 Python 标准库里的 `json` 和 `mmap` 做同样的事，输出同样的格式。

两者的输出逐字节相同才算通过。校验和用的是 FNV-1a 64 位哈希，选它是因为它在两种语言里都只要三行就能写对。

测试文件由 [`tests/make_fixtures.py`](../tests/make_fixtures.py) 生成，分两类：

- **合法文件**。包含各种类型、零维标量、有一个维度为 0 的空张量，以及一个名字里带引号、反斜杠、换行、中文和表情符号的张量。同样的内容还会用全转义的 JSON 再写一份，两份文件读出来必须一样。
- **损坏文件**，共 11 个，每个故意违反上面表格里的一条规则。读取器必须明确拒绝它们：退出码为 1 并给出错误信息，既不能崩溃，也不能当作成功。

测试程序在编译时打开了 AddressSanitizer 和 UndefinedBehaviorSanitizer，所以越界访问、内存泄漏和未定义行为也会让测试失败。

```
$ make test
ok   good.safetensors
ok   good_escaped.safetensors
ok   bad_dtype.safetensors：错误：张量 t：不支持的 dtype "F128"
ok   bad_dup.safetensors：错误：张量名重复：t
...
```

## 踩过的坑

**排序规则。** 为了让两份输出能逐行比较，两边都要把张量按名字排序。C 这边用 `strcmp`，比较的是 UTF-8 字节；Python 的 `sorted` 默认比较的是 Unicode 码点。这两种顺序在绝大多数情况下相同，但对拍不能依赖“绝大多数情况”，所以 Python 这边显式地按 `name.encode("utf-8")` 排序。

**名字里的换行。** 测试里有一个张量的名字包含换行符。如果原样打印，一个张量会占两行，逐行比对就乱了。两边都改成把控制字符按 `\uXXXX` 输出。
