# 前言

## 这本书要做什么

我们要从零写一个大模型推理引擎。大模型是用海量文本训练出来的神经网络，训练的结果是几百亿个数（叫“权重”或“参数”）；推理是拿着训练好的权重，根据用户的输入算出输出；推理引擎就是做这件事的程序。“从零”的意思是：不用 PyTorch，不用现成的推理库，权重文件怎么读、分词怎么做、每一层怎么算、显卡上的内核（在显卡上由成千上万个线程并行执行的函数）怎么写，全部自己动手。

最终目标是一个可以商用的系统：它能在一台装了两张显卡的工作站上加载一个开源模型，通过 HTTP 接口对外提供服务，并且我们能说清楚它的每一个输出为什么是对的。

你需要会 C 和 Python。不需要事先了解 Transformer（现在几乎所有大模型都采用的一种网络结构），用到的地方会讲。

## 三条原则

**先正确，后性能。** 第一卷里的每一段代码都用最朴素的写法。一个三重循环的矩阵乘法很慢，但它一眼就能看出对不对。性能优化留到第二卷，那时我们手里已经有一个可信的实现可以用来比对。

**每一步都对拍。** “对拍”是程序设计竞赛里的说法：同一个问题写两份独立的实现，喂同样的输入，比较输出是否一致。“看起来能跑”不算数。每一章都有一条可以自动检查的验收标准，通常是把我们的输出和一份独立的参考实现逐字节或逐元素比较。模型推理里最危险的错误不会让程序崩溃，只会让输出变差一点，不对拍就发现不了。

**如实记录。** 开发中走过的弯路、犯过的错、排查的过程，都会写进书里。

## 技术选择

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 引擎语言 | C（C17）加 CUDA | 内存布局、指针、显存拷贝都摆在明面上，没有隐藏机制 |
| 测试语言 | Python | 只用来生成标准答案和驱动对拍，引擎本身不依赖它 |
| 第一个目标模型 | Qwen3.8-27B | Apache 2.0 许可；名字里的 27B 指约 270 亿个参数，权重约 55.6 GB，一张 96 GB 的显卡不用量化（把权重压缩成更少的位数）就能装下 |
| 目标机器 | 两张 RTX PRO 6000（每张 96 GB 显存，即显卡自带的内存） | 前面的章节只用一张，第二张留给后面更大的模型 |

关于目标模型有一点要说明：许可证（Apache 2.0）和权重大小（18 个文件，共约 55.6 GB，全部是 16 位浮点）已经对照官方仓库核实过。其余的架构细节来自公开报道，后面的章节用到哪一项，就在那一章里核对哪一项。

## 路线

第一卷按下面的顺序推进，每个阶段一章。

| 阶段 | 做什么 | 验收标准 |
| --- | --- | --- |
| 1 权重文件 | 解析 safetensors，内存映射加载 | 每个张量的名字、形状、校验和与 Python 读出的一致 |
| 2 分词器 | BPE 编解码、特殊符号、对话模板 | token 序列与参考实现完全相同 |
| 3 张量与算子 | 矩阵乘、归一化、激活函数、softmax、位置编码（CPU） | 每个算子与参考输出的误差在约定容差内 |
| 4 单层前向 | 注意力层、前馈层 | 单层输入输出与标准答案一致 |
| 5 整模前向 | 所有层串起来，输出 logits | 贪心解码的 token 与参考完全相同 |
| 6 生成循环 | 缓存、采样、停止条件 | 带缓存与不带缓存的输出一致 |
| 7 单卡 GPU 后端 | 把算子改写成朴素的 CUDA 内核 | GPU 与 CPU 结果逐层对拍通过 |
| 8 服务层 | HTTP 接口、流式输出、取消、批处理 | 批处理与单条请求的结果一致 |
| 9 双卡 | 按层把模型切到两张卡 | 双卡与单卡结果一致 |
| 10 量化与第二个模型 | 低精度权重、MoE 路由 | 与该模型的参考实现对拍通过 |
| 11 商用化 | 工具调用、限流、日志与指标、故障恢复 | 长时间压力测试无崩溃、无泄漏 |

表里有些术语到对应的章节才会细讲，这里先各用一句话交代：

- **logits**：模型最后输出的一组分数，词表里每个 token 一个，分数越高表示模型越倾向于它作为下一个 token。
- **贪心解码**：每一步都选分数最高的那个 token。
- **缓存**：生成时把已经处理过的 token 的中间结果存起来，生成下一个 token 时不用从头再算。
- **采样**：按概率随机挑选下一个 token，而不是总挑最高的，这样回答不会千篇一律。
- **流式输出**：生成一个 token 就发给用户一个，而不是全部生成完才一起发。
- **批处理**：把多个用户的请求放在一起算，充分利用显卡。
- **MoE 路由**：MoE（混合专家）模型的每一层有很多组前馈网络（“专家”），每个 token 只挑其中几组来算，“路由”就是挑选的那一步。
- **工具调用**：模型在回答中输出一段约定格式的文字，表示要调用某个外部函数（比如查天气），由程序执行后再把结果交还给模型。
- **限流**：限制每个用户在单位时间内能发多少请求。

路线会随着开发调整，调整的原因也会记下来。
