# 前言

## 这本书要做什么

我们要从零写一个大模型推理引擎。“从零”的意思是：不用 PyTorch，不用现成的推理库，权重文件怎么读、分词怎么做、每一层怎么算、显卡上的内核怎么写，全部自己动手。

最终目标是一个可以商用的系统：它能在一台装了两张显卡的工作站上加载一个开源模型，通过 HTTP 接口对外提供服务，并且我们能说清楚它的每一个输出为什么是对的。

你需要会 C 和 Python。不需要事先了解 Transformer，用到的地方会讲。

## 三条原则

**先正确，后性能。** 第一卷里的每一段代码都用最朴素的写法。一个三重循环的矩阵乘法很慢，但它一眼就能看出对不对。性能优化留到第二卷，那时我们手里已经有一个可信的实现可以用来比对。

**每一步都对拍。** “看起来能跑”不算数。每一章都有一条可以自动检查的验收标准，通常是把我们的输出和一份独立的参考实现逐字节或逐元素比较。模型推理里最危险的错误不会让程序崩溃，只会让输出变差一点，不对拍就发现不了。

**如实记录。** 开发中走过的弯路、犯过的错、排查的过程，都会写进书里。

## 技术选择

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 引擎语言 | C（C17）加 CUDA | 内存布局、指针、显存拷贝都摆在明面上，没有隐藏机制 |
| 测试语言 | Python | 只用来生成标准答案和驱动对拍，引擎本身不依赖它 |
| 第一个目标模型 | Qwen3.8-27B | Apache 2.0 许可；权重约 55.6 GB，一张 96 GB 的显卡不用量化就能装下 |
| 目标机器 | 两张 RTX PRO 6000（每张 96 GB 显存） | 前面的章节只用一张，第二张留给后面更大的模型 |

关于目标模型有一点要说明：许可证（Apache 2.0）和权重大小（18 个文件，共约 55.6 GB，全部是 16 位浮点）已经对照官方仓库核实过。其余的架构细节来自公开报道，后面的章节用到哪一项，就在那一章里核对哪一项。

## 路线

第一卷按下面的顺序推进，每个阶段一章。

| 阶段 | 做什么 | 验收标准 |
| --- | --- | --- |
| 1 权重文件 | 解析 safetensors，内存映射加载 | 每个张量的名字、形状、校验和与 Python 读出的一致 |
| 2 分词器 | BPE 编解码、特殊符号、对话模板 | token 序列与参考实现完全相同 |
| 3 张量与算子 | 矩阵乘、归一化、激活函数、softmax、位置编码（CPU） | 每个算子与参考输出的误差在约定容差内 |
| 4 单层前向 | 注意力层、前馈层 | 单层输入输出与标准答案一致 |
| 5 整模前向 | 所有层串起来，输出 logits | 贪心解码的 token 与参考完全相同 |
| 6 生成循环 | 缓存、采样、停止条件 | 带缓存与不带缓存的输出一致 |
| 7 单卡 GPU 后端 | 把算子改写成朴素的 CUDA 内核 | GPU 与 CPU 结果逐层对拍通过 |
| 8 服务层 | HTTP 接口、流式输出、取消、批处理 | 批处理与单条请求的结果一致 |
| 9 双卡 | 按层把模型切到两张卡 | 双卡与单卡结果一致 |
| 10 量化与第二个模型 | 低精度权重、MoE 路由 | 与该模型的参考实现对拍通过 |
| 11 商用化 | 工具调用、限流、日志与指标、故障恢复 | 长时间压力测试无崩溃、无泄漏 |

路线会随着开发调整，调整的原因也会记下来。
